**`draiver metrics`: per-attempt and per-codebase agent-performance metrics folded from
session transcripts, plus attempt provenance (drv-054).** `draiver metrics TICKET` and
`draiver metrics --codebase PATH` report how accessible a codebase was to the agents that
worked it: exploration and search before the first productive edit, empty and repeated
searches, files read but never used, which docs were read (and, per codebase, which never
were), and failed tool calls split by kind — env-discovery errors (the accessibility
signal), test and build failures, edit mechanics and permission denials — alongside
outcome, review round trips, escalations and the existing token/cost figures. Metrics
are an incremental fold over normalized agent events with one table-driven tool-call
classifier that also reads Bash (`cat`, `rg`, `go test`, heredoc writes, …). Stored vs
computed is explicit: `--stored` (default) never computes and labels each row `stored`,
`missing` or `stale`; `--compute`/`--recompute` persist to `attempts/<id>/metrics.json`,
outside the hash chain, versioned by `metrics_version`. Codebase output aggregates
count/median/p90 grouped by model, with `--since`, `--sort` and `--limit` and a
`draiver ctl logs` pointer on every row; `--json` is stable and documented in
`docs/metrics.md`. Newly cut attempts now record `base_commit`, `repo_id` and
`draiver_version` in attempt.md, and the model actually used is folded in on retire;
older attempts report these as `inferred` or `unknown`.
